# Release process

1. Pin or deliberately update source releases.
2. Run source adapters and retain audit reports.
3. Review unresolved mappings, rights and contradictions.
4. Approve the release profile.
5. Build twice from clean worktrees; compare hashes.
6. Validate manifest, chunks, attribution and size budgets.
7. Publish an immutable GitHub Release.
8. Record the release URL, checksums, source versions and known limitations.

The initial process has no automatic deployment. A Hortinis operator chooses when and how an artifact becomes active.
